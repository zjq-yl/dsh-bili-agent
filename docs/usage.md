# 配置与使用

## 安装与加载 DSH

需要 Python 3.11+；本机桌面端为 `D:\app\vscode\dsh`，已用其 DSH 0.2.1-rc.5 真实依赖验证开发加载。

可以在已激活的项目虚拟环境中直接运行安装脚本。已有 `.venv` 会复用；若缺少 pip（例如由 uv 创建），脚本先用 Python 自带的 `ensurepip` 离线补齐，再用该环境自己的 pip 安装依赖。`-Python` 仅用于指定首次创建虚拟环境的解释器，不要求另找带 pip 的全局 Python。

依赖已装好时，只需运行：

```powershell
.\scripts\start-local.ps1
```

它会使用 DSH 自带 Node 构建插件、连接桌面依赖、修正补丁中的 `pythonPath` 指向项目 `.venv`，并用空闲端口启动 DSH、打开浏览器。无需运行 `package.py` 才能测试。终端保持打开，Ctrl+C 停止。若 DSH 安装目录不同，传入 `-DshDir '你的目录'`。

进入页面后，先配置或选择可用的 DSH 聊天模型，再发送“请调用 bili_agent_status，检查 B 站插件是否就绪”。收到 `ready: true` 表示 Python 核心已接通。插件的 `provider`、`model` 同时留空时继承宿主默认模型，也可显式配置；仅安装 faster-whisper 并不代表已下载 ASR 模型。

请使用本次脚本打开的浏览器页面，并新建会话。它默认是 `web` profile，与原先桌面窗口的 `desktop` profile 分开。启动终端应显示 `[dsh-bili-agent] Tools registered; status tool: bili_agent_status` 和 `[dsh-bili-agent] Python ready`；状态结果应包含 `plugin: "dsh-bili-agent"`、`tool_namespace: "bili_agent_"` 和本项目数据目录。若只出现 `bili_status`、`bili_whoami`、`bili_run` 或 `bili-duty`，对应的是其他插件，不能替代本插件验收。不要让模型用相似工具冒充检查结果。

实际工具可见性还取决于会话模式：`standard`（标准）和 `minimal` 会直接列出13个 `bili_agent_*` 工具（含好友与自动运行工具）；`ptc` 模式把它们放进 `run_code` 的工具 SDK，直接工具列表不会逐个显示。首次测试选择 `standard`，已有会话不会因为默认设置变化而自动切换模式。隔离验证检查工具目录并调用状态工具，而非仅检查插件启动日志。

本机项目补丁现使用与原桌面相同的 `deepseek-account / deepseek-flash`，并将新会话默认模式设为 `standard`。这是账号登录路由，登录失效时在 DSH 账号页面重新登录。`deepseek-official` 是另一条 API Key 路由，若主动选择它，需要在当前 Web 的模型设置页保存 `DEEPSEEK_API_KEY`。两者不要混用；不需要把 API Key 放进本插件配置或聊天。更改项目补丁后重启脚本并新建会话。

首次实际测试建议：配置账号后让 DSH 调用 `bili_agent_dm` 的 `account` 验证登录；再给它一个真实视频链接，要求获取字幕并总结。私信默认只生成草稿，发送开关和对象范围仍按下面的配置控制。

以下是等价的手动构建、配置步骤，排错时使用：

```powershell
.\scripts\setup-local.ps1
$dshDir = 'D:\app\vscode\dsh'
$dshNode = Join-Path $dshDir 'resources\runtime\primary-runtime\dependencies\node\bin\node.exe'
& $dshNode scripts/build.mjs
$env:ELECTRON_RUN_AS_NODE = '1'
& "$dshDir\DeepSeek Harness.exe" scripts/desktop-deps.mjs "$dshDir\resources\app.asar\dsh"
& $dshNode scripts/local-patch.mjs
```

`desktop-deps.mjs` 在本项目的 `node_modules/` 中连接桌面端已有依赖，不修改桌面端安装目录。移动桌面端后需要重跑。修改生成的 `data/local.patch.yml`：

| 配置项 | 含义 |
| --- | --- |
| `pythonPath` | `D:/project/dsh-bili-agent/.venv/Scripts/python.exe` |
| `dataDir` | 数据目录，默认本项目 `data/agent`；一个目录绑定一个 B 站账号 |
| `provider`、`model` | 同时留空时继承当前 DSH 的默认模型；也可同时填写一对明确的提供商 ID、模型 ID |
| `asrModelPath` | 可选，本地 faster-whisper/CTranslate2 模型目录，包含 `model.bin` 等模型文件 |
| `dmSendEnabled` | 默认 `false`；设为 `true` 才允许发送私信 |
| `dmAllowedPeers` | 允许发送的对方 UID，用逗号或空格分隔；为空则无人可发送 |
| `enablePlayer` | 默认 `false`；基础版不需要开启 |
| `enablePanel` | 默认 `true`；随插件启动本地控制面板 |
| `panelPort` | 默认 `0`；自动选择空闲端口，也可指定端口 |

```powershell
& "$dshDir\resources\runtime\cli\bin\dsh.cmd" web --patch "$PWD\data\local.patch.yml" --no-open
```

上述命令使用 `web` profile，模型配置必须在该 profile 可用。修改补丁配置后重启该宿主。该启动脚本不会更改日常使用的桌面 profile。

如果是在桌面端直接挂载 `dist/host.js`，项目里的 `data/local.patch.yml` 不会自动应用。应在那个加载位置配置 `pythonPath` 和 `dataDir`；桌面 profile 的持久加载条目可参考本机生成的 `data/desktop-plugin.patch.yml`，把该条目合并进当前 profile，而不是覆盖原有插件。`provider` 和 `model` 同时为空时，插件现会读取宿主默认选择。状态中的 `model_selection.source` 区分 `plugin`（显式配置）与 `host_default`（继承宿主），`python_path` 和 `data_dir` 用于核对当前实例。`model_configured` 只验证选中了完整路由，不代表认证或请求已经成功。

在 `dataDir/credentials.json` 中填写本人账号 Cookie 字段，值均为字符串：`sessdata`，以及发送私信所需的 `bili_jct`；`buvid3`、`dedeuserid` 按账号实际信息填写。不要把内容发给模型或提交到仓库。发送者 UID 会重新查询登录状态验证。更换账号请使用新数据目录。

## 字幕、音频和视频总结

以下是 DSH 工具参数，不是终端命令。先调用 `bili_agent_status`；配置好模型后，`bili_agent_model_check` 会进行一次模型连接测试，使用宿主模型额度。

用 `bili_agent_media` 发起后台任务，例如：

```json
{"action":"start","bvid":"替换为真实BV号","page":1,"mode":"both","transcribe":false}
```

- `mode=auto`：优先字幕；无字幕且 `transcribe=true` 时下载音频并转写。
- `mode=both`：获取字幕和音频；字幕缺失仍可单独取得音频。
- `mode=audio`：只下载音频；开启 `transcribe` 后也可从语音生成总结任务。

返回 `job_id` 后，用 `action=status` 和该 ID 查进度；`action=cancel` 取消当前媒体任务。结果包含本地音频路径、校验和、分 P/CID，以及存在时的 `summary_task`。

获取字幕或转写成功后会加入分析队列。调用 `bili_agent_control` 的 `action=start`，再用 `bili_agent_result` 和任务的 `video_id` 查看总结。已运行的分析循环会自动处理新任务。`bili_agent_fetch` 仍可直接获取字幕；`bili_agent_enqueue` 用于传入已有字幕 JSON。

面板显示“已完成分段 / 总分段”。结构或证据校验失败时，每阶段最多重新生成一次，仍失败就停下并记录阶段、字段和原因（例如 `facts[0].evidence` 引用了不存在的 ID）。两次调用均计入模型额度；不截断超长摘要、不删除错误证据来伪造通过。旧失败记录没有这些细节，只有重载新版后重试才会产生。单个完整 JSON 代码围栏可以被剥除，其他多余文字、字符串编号、臆造编号仍拒绝。

长视频先保存分段笔记，再每组最多4份笔记分层汇总，最终生成摘要与角色感受。合并结果也有检查点，重试不重复已经完成的分段或合并。层级压缩会损失细节，最终摘要不是完整逐字稿；原字幕仍用于最终证据定位。重试失败任务可点击面板“重试”，或调用 `bili_agent_control` 的 `retry`（传 `video_id`）后 `start`。

音频转文字需要运行 `setup-local.ps1 -WithAudio` 并配置**已下载完整的本地模型**，不会隐式下载模型。当前使用 CPU/int8，单次转写最多 1 小时、15 分钟执行超时；单音频下载最多 80 MiB、总缓存预算 500 MiB。下载和转写均可取消。语音转写结果保留时间戳，并明确标记 `audio_asr`。

总结只依据字幕或语音文字，不能据此推断画面或非语言声音含义。下载音频不等于已经理解音频；未转写时不会假造总结。若同时有平台字幕和 ASR，优先保留平台字幕总结，转写文件另外保存。

手动分析支持 `pause/start/stop`；失败任务用 `retry` 和 `video_id` 显式重排。自动任务在时段内入队并启动分析；点击暂停后，本次进程内不会再自动启动选片。`start` 可提供 `keyword` 开启旧的简易主题发现（最多3次搜索，每次挑1个）；每天3轮、每轮5个的完整计划使用“自动刷视频”页面。

## 本地控制面板

先重新加载 DSH 中的插件，再在项目终端执行 `.\scripts\open-panel.ps1`。自定义数据目录时传 `-DataDir '实际目录'`；也可调用 `bili_agent_status`，打开返回的 `panel.url`。面板连接当前 DSH worker，不另启机器人。关闭网页不会停止任务，点击暂停/停止按钮控制后台工作。

面板使用白色主题，分为概览、定时浏览、视频库、私信、好友、人设与记忆、操作记录。首页集中显示账号状态、当前任务、今日计划、最近视频评价和可折叠日志。好友列表优先展示，添加或修改资料时展开“添加 / 编辑好友”；推荐反馈单独折叠，私信中的反馈入口会自动打开对应表单。自动刷新只读状态；后台自动任务依据已保存的设置运行。视频库展示三档评价、理由、摘要和证据，操作记录区分平台已接受、本地记录与结果待确认。

界面布局参考 [Shadcn Admin](https://github.com/satnaing/shadcn-admin) 和 [Tabler](https://github.com/tabler/tabler) 的后台分区方式；本项目的 HTML、CSS 和图标独立实现，未引入它们的框架、组件或在线资源。更新构建后需重载 DSH 插件，再重新打开面板，以加载新样式。

视频库读取全部持久记录，每页12个，可搜索标题、UP主、摘要或BV号，并筛选“值得看 / 可以看 / 没必要看 / 待评价”。卡片展示封面、标题、UP主、时长、评价理由和摘要；点击封面或标题在B站打开对应分P。旧记录没有封面时可以点击“补全封面”，只读取视频信息，不调用模型。没有实际保存过的视频不会伪造展示。

“查看总结”展示原始摘要、带时间跳转的内容要点，以及核心问题、结论、论证过程、局限和实际收获。新版最终总结额外保存有证据约束的 `analysis`；旧结果继续可读，不自动批量消耗模型。点击“重新深度总结”会从保存的字幕重新分析，完成前保留旧结果，并重新评价视频；不会重复增长同一视频的兴趣记忆或重复主动推荐。

总览通过带认证的实时连接每秒同步状态，显示当前搜索、字幕获取、分段总结、最终汇总和评价步骤、步骤等待秒数、私信发送统计及最早可再次尝试的时间。模型只显示调用统计，不设本地日次数上限；不预估无法保证的完成或送达时间。断线后明确提示数据过期并自动重连；关闭面板不停止任务。运行日志在本地保留最近500条，面板显示最近100条，不记录凭据、模型原始输入或私聊正文。新增日志从更新版本后开始记录。

“定时浏览”的请求卡片显示每个视频的分析状态、错误及回复投递进度。没有配置好友时，总览会提示主动推荐缺少接收对象；可以在请求卡片点击“设为主动推荐好友”，核对已填入的UID和兴趣后保存。设置只影响后续主动推荐，不会自动向未获允许的账号发送。

## 每日自动探索与主动推荐

新版默认启动私信监听，并在北京时间18:00–21:00运行每日计划：18:00、19:00、20:00各启动一轮，每轮目标5个视频。搜索词来自人设的优先关键词，候选按偏好排序并排除避开词。没有可用字幕或超过默认600秒的视频跳过，每轮最多检查20个候选，不保证候选不足时也能凑满5个。自动发现以字幕为基础，不会伪造真实播放观看。

同一天的轮次持久去重。晚些时候启动DSH时，仍在时段内会补建当天已经到点的轮次；完全错过时段不补跑昨天的选片。时段限制新的搜索和入队，已经入队的分析、评价和投递可以继续完成。DSH完全退出时不运行；下次启动继续已保存的工作。插件不设本地模型次数上限；临时模型故障会保留进度，已接收的点播任务按重试策略继续。

每个新完成视频由模型结合人设和已有证据评价为“值得看”“可以看”“没必要看”，给出理由。主动推荐只选“值得看”且匹配好友明确兴趣的内容，每个视频最多推荐给3名好友。好友必须已经建档、开启推荐；自动投递还需该好友的自动发送开关、全局发送开关与UID白名单。好友的私聊正文不会进入对其他好友的推荐判断。

好友明确点播时，先从全部已完成历史中按标题和摘要检索，取最多20个候选交给模型按本次需求筛选；足够时直接复用总结，不重新搜索或转写。候选不足或模型认为不匹配时，再按配置即时搜索补充（默认最多3轮、每轮目标5个）。点播不受定时浏览窗口、主动推送时段和主动推荐每日5个上限约束，也不再设原来的每天3次、10分钟一次限制；每次仍最多选1–5个，消息去重和手动暂停继续有效。

点播选片、评价和结果投递优先于定时任务；已在进行的普通视频分析会在片段保存后让出队列，不中断正在进行的单次模型调用。明确点播可从“值得看”或“可以看”中按需求选取；日常主动推荐只选“值得看”。结果附具体理由、视频总结、局限和对应视频链接。新的明确请求有独立回复，不因为视频以前推荐过就省略；遗忘该会话后不再投递其未完成请求。当前检索是关键词候选加模型筛选，不是全库向量语义检索，不能保证每次都召回所有同义内容。

接受推荐请求时会生成确认回复，即使模型选择沉默也不会丢掉已接受请求的确认。没有匹配结果时回复说明，获取字幕或分析失败则明确说明失败；处理异常时生成进度说明（同一请求、原因、UTC日只生成一次），仍受私信发送范围和配额限制。插件已取消本地模型日次数限制。模型服务暂时失败时，已接收消息会保存并生成不依赖模型的说明；监听按轮询继续尝试，重启后仍会处理已接收但未完成的消息。点播视频因模型连接或超时失败时保留检查点，按60秒至15分钟的退避间隔自动重试；认证和权限问题仍需处理。发送冷却不会中断视频处理；只有最终推荐正文全部拿到平台回执才标记请求完成。不确定的发送不会自动重发。

模型还可以建议点赞、收藏和不喜欢。点赞与收藏通过B站接口执行，每天最多30次动作尝试，间隔至少60秒；投币、三连和评论不在此自动流程内。收藏默认选择名称为“默认收藏夹”的文件夹，找不到时停止该收藏并提示配置ID；可在面板读取自己的收藏夹再选择。动作与推荐都持久去重，发送或动作结果不确定时不会自动重放。

“不喜欢”不会调用取消点赞。当前点踩接口需要App `access_key`；未在本地凭据中配置时，仅记录本地不喜欢，并排除后续自主选片，面板显示“仅本地记录”。这是接口能力限制，不能当作B站点踩成功。[接口资料](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/video/action.md)

特别值得分享的视频可附加真实的类型7视频卡片。先发送推荐理由与链接，收到成功回执后再发送卡片；两条消息分别记录发送统计，至少间隔10秒，同一视频不重复计入主动推荐数量。卡片发送不确定时不重试，正文中的链接仍可使用。[分享消息格式](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/message/private_msg_content.md)

设置保存在当前数据目录的数据库中，可通过面板或 `bili_agent_automation` 修改。`action=status` 查看，`action=folders` 读取收藏夹；`action=configure` 的 `config_json` 仅填写要修改的字段，例如：

```json
{"action":"configure","config_json":"{\"dm_auto_start\":true,\"scheduled\":true,\"start_time\":\"18:00\",\"end_time\":\"21:00\",\"rounds\":3,\"per_round\":5,\"proactive_enabled\":true}"}
```

面板仅绑定 `127.0.0.1`，使用启动时生成的访问凭据和同源检查。访问地址写入数据目录的 `panel.json`；不要分享这个文件或完整地址。重载插件后旧地址可能失效，用打开脚本获取新地址。若端口占用，改用 `panelPort: 0`；若状态中 `panel.state=failed`，检查其 `error`。

如果旧实例没有启动面板，可先从托盘完全退出 DSH，再在源码项目终端运行 `.\scripts\repair-desktop.ps1 -PeerUid '接收者数字UID'`。它重建插件，备份并更新现有 desktop 配置中的 `bili-agent` 条目，开启面板和私信发送、加入指定 UID，然后打开 DSH 并等待面板。不会强制终止进程，也不会创建或发送测试消息。配置修改保留其他插件和已有允许对象；该命令会允许既有自动回复/推荐设置在重启后按配置发送。单独诊断面板可运行 `.\scripts\open-panel.ps1 -CheckOnly -WaitSeconds 0`。

如果窗口已关闭但后台进程仍在，脚本会等待最多10秒并列出残留 PID。保存 DSH 中的工作后，可追加 `-StopDsh` 明确强制结束进程，再继续修复；未保存的 DSH 工作可能丢失。停止前会核对所有目标进程的可执行文件路径，路径不属于指定安装目录或无法确认时拒绝停止，不会按名称批量结束其他 Electron 或 Python 程序。

## 私信收发

统一使用 `bili_agent_dm`，对方 UID 必须是字符串。

除文本外，现支持接收 B 站类型 7/8 的视频分享卡片，将标题和 BV 号作为消息上下文。卡片解析参考 `dsh-bili-scroll` 的 MIT 实现，来源与许可证见 `THIRD-PARTY-NOTICES.md`。收到卡片不会自动下载视频；若该视频尚无已保存总结，回复不能假装已看过。

| 顺序 | 参数示例 | 结果 |
| --- | --- | --- |
| 验证账号 | `{"action":"account"}` | 查询实际登录 UID，首次绑定本地数据目录 |
| 收取 | `{"action":"sync","peer_uid":"对方UID"}` | 同步该会话的最近文本消息并去重 |
| 看历史 | `{"action":"history","peer_uid":"对方UID"}` | 返回当前对象历史与消息 ID |
| 生成回复 | `{"action":"reply","msg_key":"已收消息ID"}` | 结合角色、历史和记忆生成草稿；模型也可选择沉默 |
| 指定正文 | `{"action":"compose","peer_uid":"对方UID","text":"正文","command_id":"my-message-001"}` | 创建草稿；同一次命令重试必须复用幂等键 |
| 发送草稿 | `{"action":"send","draft_id":"草稿ID"}` | 检查配置范围、账号、额度后发送 |
| 查状态 | `{"action":"status"}` | 查看监听状态和最近草稿、发送结果 |

`sync` 不传 UID 时，最多读取10个会话、每个最近30条，不保证覆盖大量积压。普通聊天和好友点播不设插件本地每日发送上限；仍保留至少60秒的发送间隔和平台风控处理，不能理解为可以无限高频发送。超时、取消或回执缺失时记为 `uncertain`，需要核对B站会话，不会自动重发。

默认在插件启动且有凭据时自动监听；发送开关开启且有允许UID时进入自动回复，否则只生成草稿。`{"action":"start","auto_send":false}` 可手动启动草稿模式。只处理监听启动后的新消息，同一对象可多轮对话；连续消息合并回复，模型调用期间新消息留给下一轮。切换草稿/自动发送模式先 `stop` 再 `start`。`stop` 在本次进程内有效，不会立即被自动任务重新开启；要关闭下次开机自启，在自动运行设置中关闭 `dm_auto_start`。登录、模型失败会明确显示，不声称已经监听成功。

真实联调顺序：重新加载插件 → `account` 验证登录 → `bili_agent_model_check` 验证模型 → 配置 `dmSendEnabled: true` 和明确的接收者数字 UID（`dmAllowedPeers`）并重新加载 → `start` 且 `auto_send: true` → 从允许的账号发送一条新私信 → 等待轮询及模型生成 → `status` 检查发送状态并在 B 站确认收件。昵称不能直接作为收件地址；不要把机器人自己的 UID 填为收件人。`NETWORK_ACCESS_DENIED` 表示执行环境拒绝网络访问，不代表账号 Cookie 无效。

## 好友分类与视频推荐

在面板“好友与推荐”中输入对方数字 UID、昵称、分类、兴趣关键词和表达偏好。档案保存在本地，按机器人登录账号和好友 UID 隔离；不会自动同步整个 B 站好友列表或推断敏感性格属性。私信回复只读取当前好友档案。

每位好友可以单独设置学习或休闲模式、已有水平、学习目标、最长视频秒数、避开关键词和不再推荐的UP主UID（也可按名称匹配）。学习模式关注能学到什么、所需基础和目标匹配；休闲模式关注兴趣与观看负担。模型必须依据已获取内容说明推荐理由，不保证只凭字幕能验证全部事实或评价画面。推荐正文附摘要、原视频链接和一处已保存的字幕时间点。临时点播的mode、level、goal、max_seconds只保存在本次任务里，不覆盖长期偏好；所有自动选片还受全局最长视频时长限制。

主动推荐默认每天每位好友最多5个视频，可调低为0–5；已保存更低上限的好友继续沿用，旧配置超过5时按5执行。按北京时间零点换日，未确认的发送尝试也保守计数。限制在实际发送的共享入口检查，自动发送与手动发送推荐草稿都不能绕过；聊天与明确点播完全不计入此上限。附加卡片是同一个视频，不多算一个推荐，但仍遵守发送间隔，跨天未发的附加卡片不再补发。

允许主动推送时间默认北京时间09:00–22:00，时段可跨午夜，起止相同表示全天；每日数量设为0可停止主动推送。面板支持“今天先别发”和“恢复主动推荐”。这些设置不阻止明确点播请求的回复，也不会扩大原有发送白名单。

发送成功的推荐可在“最近回复”点击“反馈这条推荐”，或在“好友与推荐”填写接收UID、BV号和反馈。支持喜欢、太基础、太难、太长、不感兴趣、看过了、不要这个UP：难度反馈作为后续模型匹配的实例，不自动猜测永久水平；太长会把该对象的时长上限收紧到这条视频的75%（最低60秒）；不感兴趣/看过了排除同一视频；屏蔽UP使用已核实UID，信息缺失时要求手动补充，不凭空猜测。反馈按账号和对象隔离、重复提交不会反复缩短时长。主动发送前会再次检查最新偏好。

以下完整私信指令直接处理，不依赖模型；引用他人话语或混合表达不会直接修改设置：

- `学习模式`、`休闲模式`；`学习目标：学会用Python整理表格`；`我的水平：刚学会变量和循环`。
- `今天先别发`、`暂停推荐`、`恢复推荐`。恢复只取消暂停，保留时间、数量和权限设置。
- `BV号 太基础`、`BV号 太难`、`BV号 太长`、`BV号 不感兴趣`、`BV号 看过了`、`BV号 不要这个UP`、`BV号 这个不错`。只有最近可用视频上下文唯一时才允许省略BV号；多条时会要求说明对象。

继续追问时，会提供当前好友最近收到的视频摘要及证据，便于回答“哪里有用”“这段讲什么”；其他人的私信或推荐上下文不会混入。未知内容必须说明不知道。搜索到已有总结的视频会复用缓存；点播视频在分析队列中优先，私信回复与点播筛选在模型调用等待队列中优先，已经发起的调用不会被强制打断。当前尚未实现课程计划、复习提醒或每日推荐合辑。

视频总结完成并保存记忆后唤醒模型评价。只向已建档好友主动推荐之后完成、被评为“值得看”且匹配其兴趣的视频。推荐判断由模型结合内容和好友档案完成，生成具体理由、摘要摘记和链接。每个好友是否自动接收由其“自动发送推荐”开关决定；关掉时保留草稿供手动选择。

勾选好友的“自动发送推荐”后，仍需插件 `dmSendEnabled=true` 且该 UID 在 `dmAllowedPeers` 内。主动推荐遵守每位好友的每日视频数量和发送间隔，每轮最多自动推荐一条，有待发送的聊天回复或点播结果时优先让行。同一好友、同一BV持久去重，包括分P和进程重启；发送结果不确定时不会自动重发。取消“生成推荐”会停止该好友后续自动推荐；已有草稿仍可在私信面板查看。

对应工具是 `bili_agent_friends`：`action=status` 查看档案和推荐记录；`action=save` 用 `profile_json` 保存档案，例如：

```json
{"action":"save","profile_json":"{\"peer_uid\":\"123456\",\"name\":\"示例好友\",\"category\":\"学习伙伴\",\"interests\":[\"Python\",\"编程\"],\"style\":\"喜欢简洁直接的解释\",\"recommend\":true,\"auto_send\":false}"}
```

## 长期记忆和角色

视频总结与经历保存在 SQLite，`bili_agent_memory` 用关键词检索，省略关键词可查看角色。兴趣变化需至少 3 个不同 BV 支持，单次最多 0.02、每天累计最多 0.04。

完整默认人设位于 [`src/bili_agent/prompts/persona.md`](../src/bili_agent/prompts/persona.md)，包含身份、性格、视频兴趣、理解与表达方式、记忆隐私、好友关系、推荐规则和能力边界。可以直接阅读并修改模板，重载插件后作为默认值使用。面板“角色与记忆”可编辑完整提示词并保存到当前插件数据库；已经保存的人设优先于模板，改模板不会覆盖个人设置。面板保存后下一次模型调用生效，无须重启，不重写既有总结、记忆或发送草稿。

默认角色为“小黎”，重点关注 DeepSeek、ChatGPT、Claude、Claude Code、大模型动态、AI 编程、开源模型与前沿科技，同时支持自然的日常聊天。默认检索关键词在 `src/bili_agent/memory.py` 的 `PROFILE_DEFAULTS` 中，与提示词分别配置。人设区分产品与模型、官方消息与传闻、内容判断与真实操作回执；旧账号已保存的名字和个人偏好不会被代码中的新默认值强制覆盖。

人设中的平台边界参考 [B 站用户使用协议](https://www.bilibili.com/blackboard/protocal/licence.html) 和 [消息服务使用规范](https://link.bilibili.com/h5/im/im-specification)，社区规则以[官方入口](https://member.bilibili.com/platform/convention/)为准。用户协议对未经许可的自动化获取平台服务、内容和数据有限制，消息规范约束垃圾信息、冒用身份和侵害他人权益等行为。账号主人授权不替代平台许可；这些提示词不是合规认证，也没有新增平台许可检查器或改变现有工具权限。

`bili_agent_set_profile` 必填 `name`（1–30字）、`style`（1–1000字），可选 `persona`（1–12000字）、`preferred_keywords` 与 `avoided_keywords`（字符串数组，各最多20项，每项1–50字）。可选字段省略时保留原值；关键词传空数组清空。旧版只有名字和风格的档案自动补上默认人设，既有经历和兴趣不变。

人设用于私信回复与最终视频感受，不参与客观分段事实提取。优先关键词对当前主题搜索结果的标题加权，避开关键词排除匹配标题；并不自动从长篇提示词中抽取搜索词，也不是对视频内容的完整语义过滤。好友兴趣用于推荐，自己的兴趣用于选片，两者独立。人设不能开启发送、扩大白名单、绕过配额或工具权限；聊天要求“忘记”也不会凭提示词自动删除数据库，仍需实际调用遗忘操作。

私信记忆使用 `bili_agent_dm`：

- `summarize` + `peer_uid`：总结最近 20 条对话，保存消息 ID 作为依据。
- `memory` + `peer_uid`：查看该对象的长期对话摘要。
- `forget` + `peer_uid`：清除该对象本地私信正文、摘要和草稿正文，保留无正文的去重标记，防止下次同步恢复旧内容。

自动监听在该对象累计收到至少 6 条消息后尝试形成摘要；以后生成回复时读取同一对象的记忆。私信记忆按账号和对象隔离，不会把甲的私聊作为乙的上下文。摘要属于模型推断，不代表经独立验证的事实。遗忘不删除 B 站已发送消息、宿主日志或外部备份。

## 验证边界

插件不再限制每天的模型调用次数，旧配置中的 `model_daily_limit` 自动移除。面板仅显示调用统计，私信、视频总结、三档评价和推荐不再因本地次数用完而暂停。仅因旧 `MODEL_DAILY_LIMIT` 失败的视频会保留分段进度重新排队；重新加载插件后，自动运行会恢复处理（手动暂停除外）。

自动刷视频由北京时间时段、每天轮数和每轮数量控制，默认18:00–21:00、3轮、每轮最多5个可分析视频；候选不足时可能少于5个。每段字幕最多约120秒或6000字，多层合并也需要调用。每次模型输入上限48000字符，默认自动选片最长600秒，均不属于每日调用次数上限。聊天不设每日发送次数上限，主动推荐按每位好友每天最多5个视频控制；发送间隔仍保留。

默认随插件加载启动监听；发送开关与UID白名单已配置时自动回复。调用 `dm.start` 省略 `auto_send` 会沿用这项规则，显式传 `false` 才进入草稿模式。面板可直接切换模式，已接收的回复草稿按白名单继续处理。DSH完全退出时无法监听。

私信使用事件驱动处理：接收器先将消息按账号与消息ID去重入库，再唤醒回复任务；草稿入库后唤醒独立发送任务。生成或发送等待期间接收器继续运行，回复不等待下一次接收轮询；同一会话的一批连发消息可合并回答。重启扫描已接收但未完成的消息和草稿，事件通知本身不承担持久化。不确定的发送仍禁止自动重发。主动推荐使用独立调度流程，不是触发聊天回复的条件。

状态字段 `reply_dispatch: message_event` 表示事件触发回复，`receive_transport: http_polling` 表示B站接入仍通过HTTP检查消息；不是WebSocket或平台实时回调。面板明确显示这一差别。闲聊使用独立模型通道，不再等待视频总结完成；每个通道串行，同时最多两个模型调用，仍受宿主和模型服务自身的限制。

私信面板显示上次检查、下次检查倒计时、当前处理步骤和最早可发送时间。正常以约10秒为检查周期，扣除当轮网络耗时；发送最小间隔10秒。自动回复直接检查白名单会话，不先扫描其他会话。已有会话按保存的接收进度识别新消息，重启还会恢复上次已处理消息之后的未回复消息，避免用本机启动时间误删延迟消息。首次接入不批量补回整段历史。单条格式异常最多重试两次，再给出简短说明；发送结果不确定的那条不重发，后续新消息继续处理。每新增6条消息在后台整理记忆。网络耗时和服务端排队仍影响实际速度，10秒不是送达保证。

## 视频 Agent 与聊天 Agent

两个业务 Agent 在同一 Python worker 内作为独立异步任务运行，共用小黎的人设和持久数据库，不需要第二个账号或第二份模型密钥。`automation.py` 的 `VideoAgent` 负责发现、总结、三档评价、定时计划与好友点播检索；`interaction.py` 的 `InteractionAgent` 负责持续聊天、点播结果投递、公开评论和已授权的平台互动。`messaging.py` 是聊天 Agent 的消息接收、事件消费与发送服务；`social.py` 的主动推荐循环归视频 Agent 管理。

| 场景 | 发起与执行 | 协作和限制 |
| --- | --- | --- |
| 日常闲聊 | 聊天 Agent 收到消息事件后回复 | 不启动找视频、不主动推送；连续对话无需重复开启监听 |
| 好友要求推荐 | 聊天 Agent 将需求写入 `browse_jobs`，视频 Agent 先查历史再按需搜索 | 视频 Agent 保存筛选结果并标记 `result_ready`，唤醒聊天 Agent，后者发送理由、总结与链接；不受定时浏览窗口或主动推荐5条上限限制 |
| 定时主动推荐 | 视频 Agent 分析并分类，选择值得看且匹配好友兴趣的视频，自行生成和发送推荐 | 聊天 Agent 不消费这些主动推荐；每好友北京时间每天最多5个视频，闲聊待发送时让路 |
| 公开评论 | 视频 Agent 保存总结与评价，聊天 Agent 依据人设决定是否发表评论 | 可选择不评论，只处理启用后新分析的视频；不把好友私聊或推荐对象信息提供给评论模型 |

交接结果保存在 `video_decisions`、`browse_jobs` 和发送队列表中；事件只负责唤醒，重启可恢复进度。两方不等待对方整轮任务完成。视频请求与私信请求分别排队，共用请求起始间隔；点赞、评论等写操作仍串行执行。面板首页分别显示两个 Agent 状态。

公开评论默认启用，`comments_enabled` 可关闭，`comment_daily_limit` 默认3、可设0至10，按北京时间计数，至少间隔60秒，每个视频最多评论一次。只发送有字幕证据支持的内容，不@他人、不插入链接；模型不确定或无话可说时跳过。评论只记录公开文字及回执，不读取好友私聊；发送结果不确定或进程在发送时退出，标记待核对并禁止自动重发。升级不向旧视频库批量补发评论。评论还需要已配置的账号发送权限。面板“公开评论记录”显示选择、跳过、已发及待核对状态。

本机基础依赖和 faster-whisper 安装检查已通过。用户在 DSH 中已验证账号查询与真实模型连通；完整视频汇总、实际 ASR 推理、真实私信收发及推荐仍需联调验收。本地测试使用模拟模型和平台，不能替代这些验收。运行 `.venv/Scripts/python.exe scripts/check-runtime.py` 可复查基础依赖，ASR 增加 `--audio`。仅需要旧播放器扩展时才运行安装脚本的 `-WithBrowser` 并开启 `enablePlayer`。
